## 0.5.1 correction: retain the threaded overview

On 26 October 2026 the user rejected the separate reading surface because opening a card hid the thread. Version 0.5.1 (`2026102600`) replaces F01 with inline expansion: the same post remains in its original thread, all map cards and wires stay rendered, and its column widens for reading. List view retains the post's indentation. Close/Escape collapses the card; URL navigation and per-user read persistence still work.

The DOM regression checks now assert that opened cards stay in the post container, the viewport stays visible, all connections remain, and the expanded layout has no overlaps. Expanded desktop reply and parent columns fit beside each other. Long map cards scroll internally so they do not push the entire thread far apart; List retains the full content height. The 0.5.0 evidence below is historical; its separate-reader behaviour is superseded by this correction.

## Original 0.5.0 scope and evidence

Approved scope: the nine findings in the 25 October 2026 UX report, plus its search and next-unread suggestions.
Baseline: `3d7c71c`, release 0.4.0. Target: 0.5.0 staging, `2026102505`.

| Finding | Implementation | Acceptance |
| --- | --- | --- |
| F01 | Dedicated reading surface, same DOM post and permissions | Full post uses available width up to 720 px, independently of reply depth |
| F02 | Explicit Map/List; responsive list default below 640 px available width | 320/390 px text needs no horizontal navigation; map remains available |
| F03 | Emphasise surfaces instead of applying opacity to text | Metadata colour is preserved outside the active route |
| F04 | Compact, expandable original; ordinary editor before optional quoting tools | Plain reply needs one message; quoted replies label the optional closing comment |
| F05 | Per-tab presentation state, stable post URLs, cancel returns to origin | Open post survives reload; close/cancel/back restore meaningful context |
| F06 | Moodle owns the introduction; compact module toolbar | No duplicate description or repeated visible activity title |
| F07 | Distinct new-post heading and submit label | New post/Create post differs from Post reply |
| F08 | Visible hint beside selection action | Selection activates the action; ordinary reply remains available |
| F09 | Focus remaining comment or composer disclosure after removal | Removing the last block never attempts to focus a disabled button |

Search and unread filters use the already-authorised, loaded conversation in list view. Next unread opens and persists only that post's read state. Presentation state stores only IDs/view/scroll offsets in per-tab session storage; post bodies and drafts are not cached there.

No permission, source-aware quotation, read persistence, reaction, backup or privacy contract is intentionally changed. The upgrade only advances the plugin version. Non-JavaScript details and ordinary replies remain available.

Build: `node scripts/build-amd.mjs`. Check generated modules and DOM regressions: `npm ci --prefix tests/javascript --ignore-scripts`, then `npm test --prefix tests/javascript`.

Required staging evidence: Moodle upgrade and repeat; PHP syntax and isolated Moodle PHPUnit; browser reading, map/list, filtering, quote removal, cancel, reload/back; before/after data integrity. Physical touch, screen-reader and new-participant testing remain separate from automated/desktop checks.

Rollback: retain the previous plugin directory and staging database dump before installing. Database schema is unchanged from 0.4.0; restore the matching plugin/database backup together if reverting the registered version.
